# 모바일 앱 인터페이스 계획 (2026-09-06, v2.2)

## 결론
가로 한 화면 웹앱을 기준으로 게임 흐름을 정했습니다. 타이틀 → 구단 선택 → 부임 인사 → 튜토리얼(처음만) → 정비(일정·훈련·선수단·기록) ↔ 경기(잠금) → 경기 종료 이벤트 → 정비. v2.2에서 이 흐름과 저장·불러오기, 훈련 위임, 포지션, 주루 판단, 경기 잠금까지 구현했습니다. 개별 투구 폼 훈련은 엔진이 브라우저에서 돌 때 물리에 연결됩니다.

## 1. 화면 흐름
| 단계 | 화면 | 내용 | 상태 |
|---|---|---|---|
| 1 | 타이틀 | 계속하기(자동 저장이 있으면), 새로 시작, 불러오기(슬롯 3) | 구현 |
| 2 | 구단 선택 | 6구단 카드(이름·상징색·모토). 선수단은 시즌 시작 시점의 같은 구단이고 이름·색만 바뀜 | 구현(선수단 차이는 다음 단계) |
| 3 | 이벤트 | 구단주 인사(부임 환영), 경기 종료 결과, 저장 완료 등 모달 | 구현 |
| 4 | 튜토리얼 | 처음 부임 때만 3단계(선수단 둘러보기 → 훈련 맡기기 → 일정 진행). 건너뛰기 가능 | 구현 |
| 5 | 정비 | 일정(다음 날·다음 경기·일주일), 훈련(방침 위임 또는 직접), 선수단(타순·로테이션·포지션·1군/2군·FA·카드), 기록 | 구현 |
| 6 | 경기 | 경기 날에 경기 버튼 → 선발·타순 확인 → 플레이 볼. 시작하면 끝날 때까지 다른 화면으로 못 나감(내비 잠금, 저장·타이틀 비활성). 끝나면 결과 이벤트 뒤 정비로 복귀. 일정·기록에 반영 | 구현 |
| 7 | 저장 | 헤더 저장 버튼 → 슬롯 3개. 자동 저장은 1분마다와 경기 종료 때 | 구현 |

## 2. 훈련
- 방침 위임: 직접 / 균형 / 타격 강화 / 투수 강화 / 유망주 육성 / 회복 우선. 직접이 아니면 매주 월요일에 방침대로 프로그램을 다시 배정하고, 피로 60 % 초과는 휴식으로 돌립니다.
- 개별 훈련: 선수 카드에서 프로그램을 고릅니다. 투수는 팔 각도·스트라이드·상체 기울기 슬라이더가 있고 값은 저장됩니다. 지금은 투구 은행이 미리 계산되어 있어 물리에 반영되지 않고, 엔진을 브라우저로 옮기면 pitching_params의 abd·stride·lean에 연결합니다.

## 3. 선수 데이터
- 포지션: 야수 C/1B/2B/3B/SS/LF/CF/RF/DH/OF/IF, 투수 SP/RP/CL. 선수단 목록의 셀렉트로 바꿉니다. 타순에 주요 포지션 8개가 비거나 겹치면 경고와 함께 빠른 시뮬 수비 강도가 자리마다 5 % 깎입니다.
- 타구 판단(run_iq): 주루 능력치. 안타 뒤 다음 베이스를 노릴지 송구 시간을 읽는 정확도(σ = 0.08 + 0.55·(1−판단))이고 과감성이 밀어붙입니다. 잘못 읽으면 2루·3루 주루사(single_out·double_out)가 납니다. 등급 "판단"으로 표시됩니다.
