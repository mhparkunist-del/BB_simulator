# BB_simulator 설계 정리 (2026-09-05 기준)

오늘까지의 대화와 결정을 한 곳에 모았습니다. 세부는 각 문서로 연결합니다.

## 1. 목표
Football Manager식 구단·선수 관리 위에, 실제 역학과 독립 에이전트로 경기를 시뮬레이션하는 야구 게임. 코어 엔진(`bbsim/`)은 상품화를 전제로 분리하고, 예제·보고서는 비배포입니다.

## 3. 시스템 구조
```
게임 층 (미구현)   구단·훈련·성장·시즌 루프, 자질·은닉 정보
   ↓ 선수 카드(능력치) → 물리 파라미터
에이전트 층        투수·포수·타자 (정보 경계: agents/base.py)
   ↓ 의도 + 신체 오차
물리 층            인체 운동 사슬 → 릴리스·회전축·구속·회전수 → 비행(RK4) → 배트 충돌 → 타구
   ↓
엔진 층            타석 오케스트레이션·심판·결과 모델(placeholder → 야수 에이전트)
```

## 4. 선수 모델 (docs/PLAYER_ATTRIBUTES.md)
- 계층: A 고정(골격·유전) · B 반고정(가동범위·체중) · C 훈련 가능(9축) · D 상태(일) · T 자질·재능(분야별 5성분).
- 산출 흐름: 구속 = 기저 × 사슬 보정 × 피로 × 컨디션. 회전수 = BU × 구속 × 그립 × 손목 × 악력 포화. 회전축 = 그립 오프셋 + (90° − 팔 각도) + 손목 회내. 팔 각도 = (외전 − 90°) + 측면 기울기 + 5°. 제구 σ = 반복성 × 균형 × 피로 × 집중·멘탈.
- 훈련: 슬롯 배분 → 로그 수렴, 상한은 A·B·T가 결정, 나이 곡선, 부상 위험, 폼 변경은 코칭 프로젝트.
- 자질: 학습 속도 L, 잠재 상한 P, 유지력 R, 실전 감각 G, 안정성 V. 경기 중 감각 변수 s가 σ·인식·타이밍에 들어가고 경기 후 일부가 영구 전환.

## 5. 조사·감사 결론 (1_Reference/arm_angle_research.md, 3_recent_report/…/audit/)
- MLB 팔 각도 중앙값 39.6°(5~95%: 17~57°), 릴리스 높이 1.76 m, 어깨→공 0.70 m. 70° 이상은 0.7%.
- 슬롯은 어깨 외전(84~95° 고정)이 아니라 몸통 측면 기울기가 만든다.
- v0.4 프로필 A·E는 비현실(80~90°, 2.1 m). 블라인드 감사 16건 중 15 수용·1 부분 수용(제구 σ는 엔진 재보정 필요). v0.5 프로필 확정표 있음.
