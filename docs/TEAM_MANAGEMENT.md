# 팀 관리 시스템 초안 (bbsim v1.0, 2026-09-06)

## 결론
경기 엔진 위에 얹을 "구단 운영" 층의 설계 초안입니다. 이적·트레이드·선발 라인업·육성 프로그램·은퇴·불만/만족도를 하나의 상태 기계로 묶었습니다. 각 결정이 선수 카드(bbsim/game/player.py)와 경기 엔진에 어떻게 닿는지도 정했습니다. 코드는 `bbsim/club/`에 자료형과 인터페이스(프레임)만 두었고 규칙 본체는 비어 있습니다. 참고한 게임은 Football Manager, Out of the Park Baseball(OOTP), MLB The Show 프랜차이즈, 프로야구 스피리츠·파워프로, 컴투스프로야구/9이닝스입니다.

## 1. 다른 게임에서 가져올 것
| 게임 | 가져올 요소 | 우리 반영 |
|---|---|---|
| Football Manager | 선수 성격(야망·충성·프로의식)이 만족도와 협상에 작용, 불만 → 이적 요청 → 드레싱룸 전파, 스카우팅 불확실성(능력치가 범위로 보임), 스태프 능력이 훈련 효율 결정 | 성격 3축(야망·충성·프로의식), 불만 전파 계수, 스카우팅 노이즈(이미 catcher/pitcher scouting에 같은 개념), 코칭 스태프(docs/COACHING.md) |
| OOTP | 현재/잠재 능력 이원화, 트레이드 AI가 "가치 = 현재 기여 + 잠재 × 나이 곡선 − 연봉 부담"으로 판단, 서비스 타임·연봉조정·FA·옵션·웨이버, 부상·나이 곡선, 마이너 레벨별 육성 | PlayerCard의 fixed/semi/skills/talent 위에 `value()` 함수, 계약 상태기계(신인·연봉조정·FA), 리그 규칙 플러그인(KBO/MLB) |
| MLB The Show 프랜차이즈 | 사기(morale) 5축(출전 시간·팀 성적·연봉·팀 동료·도시), 훈련 포커스 슬롯, 은퇴 결정에 나이·능력 하락·계약 | 만족도 5축, 훈련 포커스=training.CATALOG의 축 선택, 은퇴 확률 모델 |
| 프로야구 스피리츠 / 파워프로 | 특수능력(태그)로 상황별 보정, 컨디션 화살표(주간 변동), 육성 이벤트(부상·각성) | 상태(state) 컨디션 변수와 이벤트 훅, 특수능력은 자질(talent)·습관(tendencies)으로 대체 |
| 컴투스프로야구 / 9이닝스 | 스킬 육성 단계, 팀 케미(같은 팀 출신·포지션 시너지), 트레이드 카드 등가 교환 | 케미는 만족도의 '동료' 축으로만, 등가 교환은 `trade.value_gap` |
| 실제 KBO/MLB 규정 | KBO: 보류선수 65명, FA 자격(등록일수), 2차 드래프트, 외국인 3명, 샐러리캡. MLB: 40인 로스터, 옵션 3회, 서비스 타임 6년 FA, 룰5 | `LeagueRules` 데이터 클래스에 상수화, 기본은 KBO형 |

## 2. 상태 모델
```
Club
 ├ roster: List[Contract]        # 선수 카드 + 계약 + 만족도 + 역할
 ├ lineup: Lineup                 # 선발 9 + 타순, 선발 로테이션 5, 불펜 역할
 ├ finances: Budget               # 연봉 총액, 샐러리캡, 이적 자금, 수입(관중·중계)
 ├ staff: Staff                   # 코칭 스태프(bbsim/game/coaching.py 재사용), 스카우트
 ├ development: DevelopmentPlan   # 선수별 훈련 포커스·부하·마이너/2군 배정
 └ policy: ClubPolicy             # 감독 성향(유망주 우선/승리 우선), 리스크 허용
Season loop (week): 경기 → 결과·부상 → 만족도 갱신 → 훈련(Staff.run_week) → 시장(이적/트레이드 창) → 은퇴/계약 이벤트
```

## 3. 하위 시스템 규격
### 3.1 계약·이적·FA (`club/contracts.py`, `club/market.py`)
- `Contract(player, salary, years_left, status ∈ {rookie, arbitration, veteran, FA, foreign}, options, no_trade)`
- FA 자격: 리그 규칙(등록일수/서비스 타임)으로 판정. 시장 가격 = `value(player) × 리그 물가 × 수요(포지션 부족 구단 수)`.
- 이적 시장은 창(window) 안에서만: 제안(offer) → 구단 수락(가치 차 + 정책) → 선수 수락(연봉·출전 기회·팀 성적 전망·거리) 3단계. FM의 "선수 동의" 단계를 그대로 둡니다.
### 3.2 트레이드 (`club/trade.py`)
- 상대 구단 AI: `value_gap = Σ value(받는 선수) − Σ value(주는 선수)`, 정책(리빌딩=잠재 가중·컨텐딩=현재 가중), 연봉 부담 반영. 수락 조건 `value_gap ≥ −허용오차`.
- OOTP처럼 "트레이드 블록"(내놓은 선수 목록)과 "요구 포지션" 신호를 둡니다.
### 3.3 선발·라인업 (`club/lineup.py`)
- 타순 자동 생성: 출루(선구·컨택) 상위 1·2번, 타구 품질(힘·배럴) 3·4번, 좌우 투수 스플릿(split_vs_L/R)로 플래툰. 감독 정책이 수동 지정을 덮어씀.
- 선발 로테이션: 피로(pitch_count 누적·회복)와 상대 타선 좌우 비율로 순서 조정. 불펜 역할(마무리·셋업·롱)은 침착성·구위로.
### 3.4 육성 (`club/development.py`)
- 기존 `bbsim/game/training.py` CATALOG와 `coaching.Staff.run_week`를 그대로 씀. 추가: 선수별 포커스 2슬롯(The Show식), 2군 배정(경기 경험 자질 `talent.game_feel`이 실전으로만 오르게), 각성/부상 이벤트 훅.
- 나이 곡선: 27~30 정점, 이후 신체(fixed) 하강 → 감사 02 #27 반영해 완만하게.
### 3.5 은퇴 (`club/retirement.py`)
- 시즌 종료 시 확률: 나이(34+ 급증), 능력 대비 시장 가치 하락, 계약 부재, 부상 이력, 성격(프로의식 높으면 늦게). 은퇴 → 코치 전환 후보(coaching.Coach 생성).
### 3.6 불만/만족도 (`club/morale.py`)
- 5축(0~1): 출전 기회, 팀 성적, 연봉 공정성(동급 대비), 동료·감독 관계, 역할 일치. 가중은 성격(야망↑→출전·성적 가중, 충성↑→관계 가중).
- 효과: 낮은 만족도 → 훈련 효율 −, 경기 중 집중(focus) 상태 −, 이적 요청, 드레싱룸 전파(FM). 높은 만족도 → 재계약 할인.
### 3.7 리그 규칙 플러그인 (`club/rules.py`)
- `LeagueRules(roster_max, fa_service_days, foreign_max, salary_cap, draft_rounds, trade_window, waiver)`; KBO 기본값, MLB 프리셋.

## 4. 경기 엔진과의 접점
- 라인업 → `HalfInning(lineup=…)`: 카드 → `BatterProfile.from_card`, 투수 카드 → `PitcherProfile.from_card`.
- 만족도·컨디션 → 카드 state(focus·fatigue) → 실행 σ 배수(이미 derived_execution에 k_focus·k_fat 존재).
- 경기 결과 → 만족도(출전·성적 축), 부상(코칭 부하 관리), 자질 `game_feel` 갱신.

## 5. 구현 순서 제안
1. `club/rules.py`·`contracts.py`·`morale.py`(상태만) → 2. `lineup.py` 자동 타순·로테이션(엔진과 첫 연결) → 3. `development.py`(기존 코칭 재사용) → 4. `market.py`·`trade.py` 가치 함수와 AI 수락 → 5. `retirement.py` → 6. 시즌 루프 `season.py`와 저장/불러오기(감사 01 #4 직렬화 선행).

## 6. 미정 사항 (사용자 결정 필요)
- 리그: KBO형 기본으로 둘지, 가상 리그(구단 수·일정)로 갈지.
- 재정 깊이: 관중·중계 수입까지 모사할지(Baseball Mogul 수준), 아니면 연봉 총액만 제약으로 둘지.
- 사용자 개입 범위: 감독(경기 중 지시)까지인지, 단장(계약·트레이드)까지인지.

## 7. 구현 v1 (2026-09-06, 구단 사무실 페이지)
- 파일: `tools/build_club.py`가 시드로 구단을 만들고 `web/templates/club.template.html`에 넣어 `web/club_v1.0_0906.html`을 만듭니다. 페이지는 서버 없이 브라우저에서 시즌을 진행하고 localStorage에 저장합니다.
- 구단: 26명(야수 13, 투수 13: 선발 5·불펜 8)과 FA 8명. 선수마다 나이, 손, 포지션/역할, 보이는 등급(S~D, 실제값+잡음)이 있습니다. 숨은 능력치는 야수 6종(컨택·파워·선구·주력·수비·송구) 또는 투수 4종(구위·제구·체력·무브먼트)입니다. 잠재력(젊을수록 여유), 성격 3축, 만족도 5축, 컨디션, 피로, 계약(연봉·년수·신분), 시즌 기록도 있습니다.
- 일정: 4월 3일부터 월요일 휴식으로 30경기. 상대 5구단은 타격·투수·수비 강도만 가진 빠른 시뮬 상대입니다. 다음 날·다음 경기까지·일주일 버튼으로 진행합니다.
- 경기(빠른 시뮬): 타선 강도는 컨택 0.4·파워 0.3·선구 0.3에 컨디션 배수입니다. 투수 강도는 선발(구위 0.5·제구 0.3·무브먼트 0.2, 피로 페널티) 0.65와 불펜 평균 0.35입니다. 기대 득점 λ=4.6·(1+1.7·차이+0.5·수비차)+홈 0.15을 만들고 포아송으로 득점을 뽑습니다. 선발은 로테이션 순서에서 피로 75 % 미만인 투수를 고르고, 이닝은 체력에서, 타자 기록은 컨택·파워·선구 확률로 채웁니다. 상세 물리 경기는 PC판(play_pc)에서 따로 봅니다.
- 훈련: 프로그램 11종(타격, 파워, 선구, 주루, 수비, 송구, 구위, 제구, 무브먼트, 체력, 휴식). 매일 g = 0.0035·가중·(0.6+0.8·코치 역량)·만족도 배수·√(잠재 여유)·피로 페널티·강도(경기일 0.5)·나이 곡선입니다. 나이 곡선은 27세 이하 1.0, 28~31세 신체 0.5/기술 0.8, 32세 이상 신체 하락입니다. 부하가 피로를 올리고, 피로 60 % 초과와 프로그램 위험도가 부상 확률을 키웁니다(3~38일 결장). 휴식은 피로 −10 %·컨디션 +5.
- 만족도: 매주 `bbsim/club/morale.py`와 같은 식으로 다섯 축을 목표값 쪽으로 0.15씩 당깁니다. 출전(주 4경기 이상, 투수 1경기), 팀 성적(승률), 연봉 공정성(등급 대비 평균 연봉), 역할 일치(타순/로테이션), 동료(클럽하우스 평균)입니다. 종합이 0.35−0.15·충성 아래면 이적 요청이 일지에 뜹니다. 낮은 만족도는 훈련 효율을 깎습니다(프로의식이 완화).
- 선수단: 타순 9(교체 버튼 뒤 1군 타자 클릭)와 로테이션 5(셀렉트)를 고칩니다. 1군은 26명 제한이고 나머지는 2군입니다. 방출은 동료 사기 −0.02, FA 영입은 요구 연봉이 예산에서 빠지고 2군에 합류합니다.
- 순위·기록: 6구단 승률 순위(상대끼리는 강도 차로 확률 승패), 팀 득실, 타자·투수 개인 기록.
- 남은 과제: 실제 물리 경기와의 연결(PC판 라인업 넘기기), 트레이드 AI, 계약 갱신·FA 자격·은퇴(시즌 종료 처리)입니다. 2군 경기, 부상 유형, 스카우팅 노이즈의 시간 감소도 남았습니다.
